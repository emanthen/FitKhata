# Application security pass — 2026-10-13

Scope: S2's two asks — (A) a `.github/workflows/security.yml` CI pipeline,
(B) a code-review pass for IDOR/mass-assignment/file-upload/SSRF/CSV-
injection/rate-limiting. Unlike the original H1 pass
(`docs/security/AUDIT-2026-10-11.md`), this environment has real internet
access, so bandit/pip-audit/semgrep/gitleaks/pnpm-audit were actually
installed and run against the real repo — findings below are from those
real runs, not written into `security.yml` blind. Fixed in the branch
this doc ships with (`security/s2-ci-hardening`), each as its own commit.

## Code-review pass — fixed

- **Rate limiting**: `MemberRenewalCallbackView`, `MemberPassView`,
  `FacebookLeadWebhookView` were all `AllowAny` with no limit at all.
  Fixed with the existing `django-ratelimit` dependency. Doing this
  surfaced two unrelated, real, pre-existing bugs (not new code): (1)
  `Ratelimited` was never converted to a 429 anywhere in the app —
  including for publicapi's *existing* rate limit — it would 500 in
  production; fixed with `core.middleware.RatelimitMiddleware`. (2)
  `publicapi` was missing from `pyproject.toml`'s `testpaths`, so its
  20 tests never ran under `make test` or CI, hiding a real crash:
  `create_api_key`/`revoke_api_key` called `core.services.audit()`,
  which assumes every audited object has `gym_id` — `ApiKey` and
  `WebhookSubscription` don't (org-level, same category
  `saas.models.PlatformAuditLog` exists for). Every Enterprise API key
  creation or webhook subscription would have 500'd in production.
- **CSV/XLSX formula injection**: `reports/exporters.py` and
  `members/tasks.py`'s import error-report wrote values straight
  through. Fixed with `core.domain.csv_safety.escape_formula_prefix`.
- **SSRF**: `WebhookSubscription.url` had zero validation before
  `requests.post()`. Fixed with `publicapi/url_safety.py`, checked at
  create time and again immediately before every delivery (DNS
  rebinding), plus `allow_redirects=False`.
- **File uploads**: member photos, waiver PDFs, coaching progress
  photos had no size cap and no real content verification; photo EXIF
  (can carry GPS) was kept verbatim. Fixed with `core/validators.py`
  (Pillow-based image verification + EXIF-drop-on-save, `%PDF-`
  magic-byte check, size caps) — storage/signing were already adequate
  (`AWS_QUERYSTRING_AUTH=True` globally, coaching's private bucket +
  5-minute signed URL), so this didn't touch that.
- **Mass assignment**: already clean — every serializer spot-checked
  uses explicit `fields=[...]` + `read_only_fields`, zero
  `fields = "__all__"` anywhere. No action needed.
- **IDOR**: `tests/idor/test_cross_gym_404.py` adds HTTP-layer
  regression coverage (`tests/rls/test_isolation.py` only proves the
  ORM/raw-SQL layer). Not a new-findings search — `docs/security/
  AUDIT-2026-10-11.md` already individually reviewed every raw-pk
  `get_object_or_404` call site and judged each safe (signed-token-
  scoped, global catalog, or platform-staff-gated); these are
  regression tests for that judgment, not a correction of it.
- **Reflected XSS**: semgrep (`p/django`) found both the WhatsApp and
  Facebook Lead Ads webhook handshake views echo
  `request.query_params["hub.challenge"]` into `HttpResponse`, which
  defaults to `text/html` — gated behind a secret verify-token match
  (low practical risk) but cheap to close with an explicit
  `content_type="text/plain"`, which is what actually stops a browser
  from ever executing an injected payload. Suppressed the semgrep rule
  at the exact matched line with that reasoning on record, since the
  rule can't model a non-HTML content-type as a fix.

## Dependency findings — fixed where safe, flagged where not

- **bandit** (`-ll`, production code only): 0 Medium/High/Critical.
  Clean.
- **pip-audit**: `pytest` 8.4.2's known CVE, fixed in 9.0.3 — dev-only,
  bumped (full suite re-run: 663/663 passed on 9.1.1).
- **pnpm audit --prod**: `postcss` (transitive via `next`) had two
  High advisories — `pnpm.overrides` pin to `^8.5.18`. `shadcn` was
  miscategorized under `dependencies` despite being a dev-only CLI tool
  with zero imports anywhere — moved to `devDependencies`, which also
  removed its transitive `braces` DoS advisory from the prod audit
  surface (already a known, accepted gap per H1; this just correctly
  reclassifies where it sits).
- **gitleaks** (Docker, full git history, 25 commits): 22 hits in
  `shared/qr_vectors.json` (CLAUDE.md rule 12's deterministic cross-
  language QR test vectors), the test-only `FIELD_ENCRYPTION_KEY` in
  `config/settings/test.py` (already commented as deterministic, no
  default in `prod.py`), one throwaway test-user password. Added
  `.gitleaks.toml` with a per-file allowlist and a comment why for
  each — exactly what H1's prompt asked for test fixtures specifically.
  Re-ran after: 0 leaks.
- **semgrep** (`p/django`, `p/python`, `p/secrets`, `p/owasp-top-ten`
  against `apps/api`; `p/typescript`, `p/react`, `p/nextjs`, `p/secrets`
  against `apps/web`; `p/secrets` against the whole repo): 2 real
  findings, both the reflected-XSS webhook handshakes above. 0 after
  fixing.

### Flagged, not fixed — both need a deliberate decision, not a blind bump

- **Django 5.1.15 has 9 known CVEs (pip-audit) with no fix inside the
  5.1 branch at all** — every fix starts at 5.2.x/6.0.x/6.1.x.
  `CLAUDE.md` pins Django 5.1 as part of the fixed stack; a framework
  major/minor upgrade isn't this pass's call to make unilaterally. This
  is the single most consequential finding in this whole pass — 5.1 is
  past its patch window and there is no way to clear these without
  moving off it.
- **next-intl 3.26.0 has two real CVEs** (open redirect, prototype
  pollution) fixed only in 4.9.1+ — no 3.x fix exists either. Checked
  this app's actual usage: neither trigger condition
  (`localePrefix: 'as-needed'`, `experimental.messages.precompile`) is
  configured anywhere, so real exposure today is low — but a 3.x→4.x
  bump is a major-version jump into an app just heavily wired to
  next-intl's current API across the entire admin console (Track 1's
  612-key i18n rollout). Upgrading that blind, with no dedicated
  regression pass, isn't this session's call either.

## `.github/workflows/security.yml` — what's real vs. written-correct

gitleaks, semgrep, bandit, and pip-audit above were genuinely run
locally against this repo and the findings are real, not assumed. Trivy
(image scan) and OWASP ZAP (DAST against a running stack) need a built
image / a fully-up, seeded compose stack respectively — written into
the workflow correctly (standard, current actions) but their first
actual execution happens in GitHub's own CI, not here. Said so in the
workflow's own comments rather than claim a result never observed.
