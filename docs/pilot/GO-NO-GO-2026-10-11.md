## Update: Docker available this session — ran it for real

Every prior pass in this doc was static review only ("no Docker in this
environment"). This session had Docker, so the NFRs marked **Not
verified** above were actually executed, not just read:

- **`make migrate` on a genuinely fresh database — found a real bug.**
  `saas.0003_seed_fitkhata_platform_gym` runs its `RunPython` under
  `system_context()` (`SET LOCAL ROLE fitkhata_system`), but had no
  migration dependency on `core.0003_system_role_grants` — the migration
  that actually grants `fitkhata_system` table access. Django's planner
  happened to order the seed migration *before* the grants on a clean DB
  (position 5 vs. 82 in `migrate --plan`), so it failed with `permission
  denied for table gyms_organization` every time. This would have broken
  the very first deploy to a fresh VPS — exactly the Phase 0B acceptance
  check ("fresh VPS → provision.sh → first deploy works end to end") that
  nothing had actually run before now. Fixed by adding the missing
  dependency (`apps/api/saas/migrations/0003_seed_fitkhata_platform_gym.py`).
- **`make test` — 573 passed, 1 failed, now 573/573.** The one failure
  (`test_touch_device_heartbeat_sets_last_seen_at`) was a test bug, not a
  product one: it called `touch_device_heartbeat()` directly without the
  `app.gym_ids` scope that `core.middleware`'s real device-auth path
  always sets before this function runs, so the RLS-scoped `.update()`
  silently matched zero rows. Fixed the test to wrap the call in
  `tenant_context([gym.pk])`, matching the real request path.
- **`make test-rls` — 16/16 passed for real**, not just "every tenant
  table has a policy" by static grep.
- **`pnpm test` (web) — 79/79 passed.**
- **`pnpm audit` — 14 criticals → 0.** Bumped `orval` (7.3→8.41, fixes 4
  RCE advisories) and `vitest` in both `apps/web` and `apps/bridge`
  (2.1→3.2.7) plus a `pnpm.overrides` pin on `tinypool` (→2.1.2, fixes the
  prototype-pollution RCE vitest's own dependency tree was still pulling
  in even at the latest 3.x). All three are dev-only tooling, never
  shipped; re-ran both apps' test suites after each bump (79/79 web,
  36/36 bridge) before keeping the change.
- **Cross-org member transfer: fixed.** `members.views.MemberViewSet.transfer`
  now catches `transfer_member()`'s `ValueError` and raises DRF's
  `ValidationError` (400) instead of letting it 500. Added a regression
  test (`test_transfer_to_other_org_gym_returns_400_not_500`).

**Still not run, still needs real infra this session didn't have:** the
k6 load scripts against a live target, and an actual restore-from-R2
drill. Those two are unchanged from the original report — everything
else in the "not verified" NFR table above is now verified, not just
reviewed.

## Update: admin console i18n — the blocking item is fixed

The one item this report called **blocking for a Nepali-first pilot** —
0 of 48 admin/super-admin pages wired to next-intl — is done. All 45
remaining pages (3 already had it: `layout.tsx`, the dashboard, and
`settings/page.tsx`) now use the same `useTranslations("admin")` pattern,
across every section: members, billing/POS, coaching, retention, reports,
notifications/settings, staff, and the super-admin platform console.
612 new keys added (688 total in the `admin` namespace), with natural
Nepali translations reusing the existing vocabulary for common actions
(Save/Cancel/Close/etc.) rather than re-translating them inconsistently
page by page. Verified, not just claimed: every `t("...")` call across
all 53 touched files resolves to a real key (0 gaps), ICU placeholder
names match between `en.json`/`ne.json` for every key (0 mismatches),
`tsc --noEmit` and `eslint` are clean, and both the Python and web test
suites still pass.

Left deliberately untranslated (consistent across all areas, not a
gap): actual data (names, phone numbers, dates, amounts), backend-only
identifiers (template keys, enum values), proper nouns (eSewa, Khalti,
Tally), and loading-state `"..."` ellipses. One pre-existing display gap
noted but not fixed (out of scope — not a translation issue): the
retention batch-freeze summary line renders a raw `freeze.reason` enum
value untranslated.
